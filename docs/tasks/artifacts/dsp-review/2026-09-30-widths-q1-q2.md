# DSP-REVIEW.1 evidence — widths and accumulator semantics (catalog §5, questions 1–2)

Measured `2026-09-30` by extracting the text layers of the three catalogued TI manuals
(`pdftotext` into `target/dsp-review/`, untracked scratch; every fact below carries its
quote's locator). Manuals: `TI-C64X-SPRU732J`, `TI-C66X-SPRUGH7`, `TI-C674X-SPRUFE8B`
(all catalogued and cached; `materials/catalog.sexp`).

## Q1 — operand, product, accumulator, guard, output widths

**C64x (SPRU732J).** ALU operands 32-bit, with 40-bit "long" on .L/.S and 64-bit
doubleword: "Most data lines in the CPU support 32-bit operands, and some support long
(40-bit) and doubleword (64-bit) operands" — §2.3 "Functional Units", printed p. 29.
Products: 16×16 → 32-bit, 32×32 → 64-bit ("an extra write port has been added from the
multipliers", §2.3 p. 29; MPY32's description, p. 321). **No accumulator register and no
guard bits — measured absent**: `guard` appears only in legal boilerplate, `accumul` only
in a mutual-exclusion example (§9.3.2); MAC-style accumulation is explicit ADDs into
32-bit registers or 40-bit pairs. Writeback: 32-bit per register; 40-bit results span an
odd:even pair with the odd register's upper 24 bits zero-filled ("Operations producing a
long result zero-fill the 24 MSBs of the odd-numbered register", §2.2 p. 26).

**C66x (SPRUGH7).** Raised datapath: .L/.S 64-bit, .M up to 128-bit sources and results
("The .M units now support up to 128-bit source operands … it includes two 64-bit write
ports", §2.3 p. 2-5). Products 32/64/128-bit (QMPY32 keeps the lower 32, §4.239;
128-bit quad results via QSMPY32R1). Accumulator/guard bits: **measured absent** (same
searches). Writeback adds **128-bit register quadruplets** `A3:A2:A1:A0…` (Table 2-2,
p. 2-4): "Values larger than 64-bits (such as 128-bit quantities) are stored in a pair
of register pair" (§2.2, p. 2-3/2-4).

**C674x (SPRUFE8B).** The C64x+ fixed-point datapath plus floating point (Table 2-2's
"Floating-Point Operations" column, p. 29–30; SP/DP = 32/64-bit). Widths as C64x; no
128-bit (measured: `128-bit` 0 hits). Accumulator/guard: **absent** (same searches).

## Q2 — fractional formats and the scaling locus

- **Q-notation is nearly absent**: `Q15` appears in NONE of the three; `Q31` appears
  exactly once, in C66x's QSMPY32R1 ("…normalizes the result to lie within -1 and 1 in a
  Q31 fractional number system", §4.241, p. 4-512). "Fractional formats" as named data
  types are not a TI C6000 concept in these manuals.
- **Scaling is instruction-encoded, not a mode bit**: the S-prefixed multiplies
  left-shift by 1 with saturation (SMPY: "The result is left shifted by 1 … saturated to
  7FFF FFFFh", SPRU732J p. 406–407; SMPY32 likewise into 64-bit, p. 416), and rounding
  variants exist (MPYIHR adds 2^14 then >>15, p. 295). ⛔ Measured trap: the literal `s`
  bit in the opcode maps is the A/B side-select, NOT a scaling bit (the MVC instruction
  text) — a misreading that would invent a scaling mode that does not exist.
- **The 40→32 bridge is an instruction**: SAT ("Saturate a 40-Bit Integer to a 32-Bit
  Integer", SPRU732J p. 381; SPRUFE8B p. 437), with the SAT bit in CSR and the SSR
  (C64x+; §2.9.13 p. 54) as the sticky-status surface.

## Widths that do not fit a plain 32/64 scalar register model

40-bit long (all three), 64-bit pairs (all three), 128-bit quadruplets (C66x only).
None has an accumulator or guard-bit mechanism.

## First classification (the `.7` report refines this)

- **Register pairs/quads as first-class widths** (40-bit in an odd:even pair with a
  zero-fill rule; 128-bit quads on C66x): the current abstraction's register file is 32
  independent XLEN registers — it *cannot express* "this pair is one 40-bit value with
  the odd register's upper 24 bits zero-filled" as a state fact. Candidate change:
  register GROUPING with a declared width and fill rule. (Cost measured at `.7`.)
- **No accumulator/guard state needed** for these targets — the measured absences mean
  the abstraction need not grow either; recorded so nobody adds them speculatively.
- **Scaling/saturation as per-instruction effects** (the S-family, MPYIHR's round,
  SAT's bridge, the SAT bit/SSR flags): expressible as ordinary instruction semantics +
  status-register state IF the flag is architectural state — a state-census question
  when a DSP profile exists, not an abstraction change today.
- **Honest limit:** three manuals from ONE vendor's C6000 family. The C28x and C55x
  manuals are cached but not yet reviewed; no non-TI DSP manual is catalogued.
  `DSP-REVIEW` never claims DSP compatibility (the tree's non-goals).
