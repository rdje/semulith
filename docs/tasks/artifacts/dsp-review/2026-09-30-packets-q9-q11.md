# DSP-REVIEW.4 evidence — issue groups and exposed sequencing (catalog §5, questions 9–11)

Measured `2026-09-30` over the same three catalogued TI manuals' extracted text layers.
This is the leaf the tree predicted would break the scalar shape ("the single most likely
place", the leaf's own acceptance). **Measured verdict: it breaks — twice.** The two
breaks are named and located below; nothing is resolved by intuition.

## Q9 — issue groups, and when operands are observed

- **The execute packet is the issue group**: "The p-bit (bit 0) determines whether the
  instruction executes in parallel with another instruction… All instructions executing
  in parallel constitute an execute packet. An execute packet can contain up to eight
  instructions. Each instruction in an execute packet must use a different functional
  unit." (C64x §3.4, p. 65; C66x §3.5, p. 3-11; C674x §3.5). Packets may span fetch
  packets; compact (16-bit) instructions carry p-bits in the fetch-packet header.
- **All of a packet's operands are observed simultaneously at E1**: "Parallel instructions
  proceed simultaneously through each pipeline phase" (C64x ch. 4, p. 509); the delay-slot
  table pins every read to cycle i (E1) while write cycles vary by instruction type
  (Table 3-3, p. 64).
- Branching into a packet's middle ignores the lower-addressed instructions (§3.4.2,
  p. 67).

## Q10 — delayed results, interlocks, early reads

- **The delay-slot table is the contract** (C64x Table 3-3, p. 64; C66x/C674x Table 3-8,
  p. 3-10 / p. 74–75): Load 4 ("The loaded data is written into the register file in
  cycle i + 4"), Branch 5, 16×16-multiply 1, 4-cycle ops 3; C674x adds FP rows AND the
  32-bit integer multiply with functional-unit latency > 1; C66x adds DP rows with
  latency 2–3 ("a new instruction can be started on the unit each cycle" FAILS for
  several FP ops). C66x is binary-compatible with C64x+/C674x on every delay count
  (measured statement, p. 3-9) — new opcodes were created rather than changing old
  latencies (FMPYDP vs MPYDP).
- **No interlocks, by design**: "Control of the pipeline is simplified by eliminating
  pipeline interlocks." (C64x ch. 4, p. 509; same sentence in the other two). The ONLY
  hardware stall is the cross-path one, and it explicitly does NOT cover loads: "no stall
  is introduced if the register being read has data placed by a load instruction"
  (C64x §3.7.4). An early read gets the stale value — the programmer's problem, not the
  hardware's.
- Load/store ordering to one location is architecturally defined even in parallel (the
  old value loads, the new stores, §4.2 p. 522).

## Q11 — the architectural status of conflicts

- Same unit twice in one packet: "invalid" (§3.7.1, p. 68).
- Two writes to one register in one cycle: **"the result is undefined"** (C64x §3.7.8,
  p. 73) — and the assembler's detection is partial by its own figure (branch-conditional
  conflicts "might not be detected").
- ⛔ **The §3.7.2/§3.8.2 contradiction, recorded not resolved**: C64x (p. 68–69) and C674x
  (p. 78) print TWO terminal outcomes for the same .M-unit conflict — "will result in an
  exception" AND "will result in erroneous values" as separate sentences; C66x (p. 3-15)
  prints the resolved form — "an exception AND erroneous values". A model must pick; the
  manuals as printed disagree with themselves, and C66x's text suggests the older ones
  lost a conjunction.

## The two measured breaks of the scalar step model (the leaf's question, answered)

1. **The unit of progress is the PACKET, not the instruction**: up to eight instructions
   read their operands simultaneously at E1 and retire on one clock's schedule. The lab's
   evaluator steps ONE instruction at a time (`OB-ENV-PARTIAL-PROGRESS`: every
   instruction completes or faults as a unit). A packet of two stores to one address has
   a defined joint outcome; stepping them individually is a different semantics.
2. **Results land LATE and interrupts land INSIDE the window**: a load's result is
   written at cycle i+4 with the window architecturally visible (early reads are stale,
   unprotected); on an interrupt, instructions that entered E1 complete through E5 and
   later packets are annulled WITHOUT state change (C64x §5.4.3, p. 547), and post-return
   code "can appear… to have fewer delay slots than they actually have" (§5.7.1, p. 557 —
   the manual's own worked LDW/ADD example produces incorrect results). ⭐ This is the
   measurement `.2` fed in: SAT's one-cycle-late flag update is the small form of the
   same shape.

   Both breaks reopen `state.sexp`'s hidden-state census by its own rule ("Every
   extension added later reopens this census"): a DSP profile carries pending-writes
   state (the in-flight window) and packet state — two candidates the RV64I census
   measured absent.
