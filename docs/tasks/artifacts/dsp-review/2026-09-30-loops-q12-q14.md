# DSP-REVIEW.5 evidence — loops, repeats and interrupt interaction (catalog §5, questions 12–14)

Measured `2026-09-30` over the same three catalogued TI manuals' extracted text layers.
Manuals: `TI-C64X-SPRU732J`, `TI-C66X-SPRUGH7`, `TI-C674X-SPRUFE8B`.

## Q12 — hardware loops vs interrupts and exceptions

**SPLOOP is C64x+-and-later only** — measured by the compatibility fields ("C64x+ CPU",
SPRU732J p. 426): plain C64x has no hardware loop buffer. The mechanism (C64x ch. 7 /
C66x ch. 8 / C674x ch. 7, essentially verbatim):

- **Loop state, fully enumerated** (§7.4/§8.4): the loop buffer (up to 14 execute
  packets), the loop-buffer count register LBC (**not user-visible; TWO of them for
  overlapped nested loops**), the inner-loop count ILC (with a 4-cycle load-to-use
  latency), the reload register RILC, and TSR/ITSR/NTSR's SPLX bit.
- **Interrupt mid-loop**: the loop DRAINS to a stage boundary first; latency grows by the
  epilog; and short loops are **not interruptible** at all ("SPLOOP loops … with ILC <=
  (ceil(dynlen/ii) + 3) are not interruptible", §7.13.1 p. 606–607 / §8.13.1 p. 8-36).
- **Exception mid-loop**: the opposite rule — "The exception is recognized immediately
  and the loop buffer becomes idle. The loop buffer does not execute an epilog to drain"
  (§7.13.3, p. 608). Interrupts drain; exceptions don't.
- **Restart**: on return, the SPLOOP re-executes and REFILLS the buffer under modified
  rules (§7.13.2: parallel instructions not executed, SPMASK ignored in the buffer,
  SPLOOPD→SPLOOP, "the interrupt return code must restore the value of ILC 4 cycles
  before the SPLOOP(D) instruction is executed"). The ISR must save/restore ITSR/NTSR,
  ILC, RILC (§7.13.1, p. 607).

## Q13 — multi-access instructions

- LDDW/STDW (64-bit, doubleword-aligned, both halves of one LD path, §3.7.5);
  LDNDW/LDNW/STNDW (nonaligned 64/32-bit) — "No other memory access may be used in
  parallel with a nonaligned memory access" (§3.7.5, p. 70–71).
- Up to TWO memory accesses per cycle, one per .D unit ("Two load and store instructions
  using … the same register file cannot be issued in the same execute packet").
- **Measured absent**: load-multiple/store-multiple (0 hits ×3), non-temporal loads
  (0 hits ×3 — LDNDW is nonALIGNED, not non-temporal), 128-bit loads/stores (C66x's
  .M-unit quads compute 128-bit but the .D unit is unchanged — "Except for the .D unit
  which remains unchanged", C66x §2.3 p. 2-5).

## Q14 — ordering for DMA / buffers / streams

- **C66x only: MFENCE exists** (§3.8.12.1 p. 3-19/3-20; §4.178 p. 4-395): "stalls … until
  the completion of all the CPU-triggered memory transactions" (cache fills, writebacks,
  coherence ops, prefetch); "MFENCE always wait at least 5 clock cycles" (sic) before
  checking busy; interrupts are still serviced mid-MFENCE and the RETURN lands back on
  the MFENCE's packet. Restrictions (alone in its packet, not in SPLOOP regions) are
  printed as "not enforced by hardware" — violated restriction = undefined-by-omission.
- **C64x/C674x: no fence, no architectural DMA-vs-CPU ordering** (measured: `MFENCE`,
  `memory fence`, `coheren` 0 hits in body text) — the manuals defer to the programmer's
  guide. Recorded so the catalog knows WHERE that answer must come from.

## SEM-04 framing (the acceptance's exact ask): restart state vs partial progress

- **Loop restart state** = {return pointer (IRP/NRP naming the SPLOOP packet), the TSR
  copy with SPLX, ILC, RILC} + re-execution of SPLOOP to refill the buffer. The partial
  loop progress that persists is exactly ILC (the remaining iterations).
- **Multi-cycle instructions keep SEM-04's shape across interrupts**: instructions that
  entered E1 complete through E5 ("Complete all pending register writes", §7.13.4);
  annulled packets "do not modify any CPU state" (§5.4.3, p. 547). Every in-flight
  instruction completes as a unit; every not-yet-E1 instruction leaves no state. ⚠️ But
  the `.4` finding stands beside it: completion-while-later-code-is-refetched is itself
  observable (the single-assignment hazard) — SEM-04 holds per instruction, and the
  PACKET/window semantics are where the scalar model breaks, measured there.
- MFENCE restarts as a whole (IRP points at its packet) — a multi-cycle instruction
  whose interrupt behavior is to RE-EXECUTE.

   presumably meant to cover reload.
2. MFENCE's restriction violations are "not enforced by hardware, and correct operation
   is not guaranteed" — undefined-by-omission, recorded as printed.
3. MFENCE prose typos ("always wait", "it's final destination") — grammar only.
4. DMA ordering is out of scope of all three CPU manuals by their own deferral — the
   catalog's answer must cite the programmer's guide, not these documents.
5. §7.13.2's "BNOP label,n … executed as NOP n + 1" states no reason at the rule.
