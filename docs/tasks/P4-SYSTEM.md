# P4-SYSTEM: validate the processor Linux actually needs

## Metadata

- Tree ID: `P4-SYSTEM`
- Status: `active`
- Roadmap lane: `ROADMAP.md` §6 → **P4 — Validate the processor needed for Linux**
- Gate: `CPU-SYSTEM`
- Depends on: `P2-SCALAR` (gate `CPU-LAB`)
- Unlocks: the CPU release gate, and with it `P5-BOARD` and `MC-MULTICORE`
- Created: `2026-09-13`
- Owner: repo-local workflow

## Goal

Select and validate a Linux-capable profile — provisionally RV64GC with an explicitly chosen
privilege revision, M/S/U modes, Sv39 translation, implemented CSRs, interrupt acceptance,
counter behaviour, and stated firmware/toolchain requirements — as a **processor**, in the
laboratory, before any board exists.

## Non-Goals

- No board, no boot. Booting does not prove the CPU, and a CPU bug found during a later boot
  returns here and invalidates affected evidence (`docs/CPU_ENVIRONMENT.md` §5).
- No floating-point support until its backend passes qualification. There is **no silent
  native-float or FFI fallback** (`docs/ARCHITECTURE.md` §6, `RUST-01`).

## Acceptance Criteria — gate `CPU-SYSTEM`

The complete declared profile passes the processor gate, **including its environment contract**.
This gate authorises the planned next engineering stage: board implementation.

attributes, event-delivery point, ordering, and cold reset. The scalar contract's
eight assumptions minus fetch leave seven, but virtual time already has a v1
replacement and partial progress is covered by the GC guarantee plus atomic
responses. Code visibility is OB-GC-FENCEI and the typed memory provider. Do not
copy scalar rules saying no asynchronous interrupt, 32-bit fetch, no memory-model
claim or integer-only reset into this composition.

The five new records must state physical requests versus translated guest VAs,
8-bit byte addresses, B/H/W/D data widths, exact full responses or failures,
alignment before translation, executable main memory without MMIO, little-endian
storage, instruction-boundary interrupt evaluation, one-hart sequential ordering
as a legal RVWMO subset, and the full declared cold state. Negative response-shape
or schedule fixtures are **contract violations**, not architectural trap causes.
Warm reset, external IRQ sources and multi-agent reservations remain out of scope.
