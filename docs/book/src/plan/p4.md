# P4 — the Linux CPU profile

**Deliverable: the processor Linux actually needs, validated as a processor.**

Select a Linux-capable profile — provisionally RV64GC with an explicitly chosen privilege
revision, M/S/U modes, Sv39 translation, implemented CSRs, interrupt acceptance, counter
behaviour, and stated firmware and toolchain requirements. *Provisionally* is load-bearing:
the exact dependency closure is resolved before the profile is claimed, not assumed from the
letters.

## The new work

System transitions, page walks and their permitted side effects, protection, atomics, floating
point, instruction visibility, faults, and restart obligations — all implemented and
independently tested **in the laboratory environment**, not by booting something and seeing
whether it complains.

## The floating-point condition

Floating-point support is not included until a named Rust implementation has passed its own
qualification task: the exact target policy for rounding modes, flags, result bits,
conversions, NaN payloads and boxing; the ancestry inventory (shared SoftFloat lineage, target
specialization, thread-local versus global status handling, exact compiler and features); and
independent numeric fixtures.

If no suitable Rust implementation passes, the required subset is implemented in Rust and the
corresponding CPU capability is deferred until validated. There is **no silent native-float or
FFI fallback** — that would make the host's floating-point defaults into the guest's semantics.

## The profile, resolved: `rv64gc-lab-v0` (`P4-SYSTEM.1`, 2026-10-03)

The provisional letters are now an exact, source-located selection. RV64I plus **M, A, F, D,
C, Zicntr, Zicsr, Zifencei**, with **Sstc** on the privileged side — ISA string
`rv64imafdc_zicntr_zicsr_zifencei_sstc`; **M/S/U** modes; **Sv39** translation; IALIGN 16

SBI 2.0 as the firmware contract the P6 boot route will execute. Every element cites the
pinned publication: the pinned v20260120 snapshot was measured to *carry* the privileged
chapters (24 `priv/` + 46 `unpriv/` pages, every cited row re-hashed against the tracked
`SHA256SUMS`), so the privileged evidence base is citable today — a 2026-09-27 census note
that called the privileged volume "absent from this snapshot" is measured false and
superseded.

The dependency closure is measured, not inferred: G = IMAFD + Zicsr + Zifencei (the naming
chapter's own definition), D depends on F, F depends on Zicsr, and C decomposes as Zca plus
Zcd at RV64 with D. The floating-point condition above becomes concrete in the resolution:
F and D are **in** the profile because the standard RV64G userspace ABI (LP64D) requires D —
and the model implements none of it until `P4-SYSTEM.7` qualifies a backend; the CPU-SYSTEM

The unit (`profiles/rv64gc-lab-v0/`) is deliberately **unregistered** and declares the new

guest-corpus document beside the declaration.

## Privilege and mode transitions: `.2` underway (slices a–f, 2026-10-03)

The leaf runs in eight checkpoints; slice (c) split cleanly into (c1) — zero Rust — and
(c2). Slice (a): the upstream census measured what the brief delegated — Zicsr's
six instructions are real rows in riscv-opcodes' `rv_zicsr`, mret/wfi live in `rv_system`,
sret/sfence.vma in `rv_s`, and Zicntr's rdcycle/rdtime/rdinstret exist **only as
pseudo-ops of csrrs** — Zicntr adds no encodings, so the fragment layer gained a
`(pseudo …)` construct (assembler spellings the disjointness gate decides under a
specialization rule, never instructions). The new tables are pinned in the unit's own
`references.sexp`; the fetch route follows upstream's move of the tables to `extensions/`
(byte-identical, measured). The assembler gained the csr operand field (positions derived
from the pinned `arg_lut.csv`, names from the pinned `csrs.csv`) and profile-derived
IALIGN (32 for rv64i, 16 for rv64gc).

Slice (b): the semantics language learned privilege — eight operators
(`field`, `inst`, `mode`, `csr-state`, `csr-read`, `csr-write`, `trap-deliver`, `xret`),
with the CSR permission model carried uniformly inside `csr-read`/`csr-write` (address
mode bits, read-only bits, counter-enables, STCE, TVM) rather than per instruction, and

Slice (c1): the state layer learned the same shape — a `privilege_mode` element (hart
state, not a CSR) and the `csr` construct with per-field WPRI/WARL/WLRL tables, and the
rv64gc state document itself: all 33 committed CSRs with their disciplines, resets and
locators, the SEM-08 hidden-state census re-earned for the privileged state. Because a
state document inside the unit is a refused route contradiction until the flip, it is
authored and fully validated from a staged path and moves unchanged at the flip — and the
gates gained the two arms the exploration measured missing: the profile's CSR list and the
state document's CSR set must agree exactly, and every CSR (and the mode) must carry a
reset. gen_state now emits both profiles, rv64i byte-identical; its composed-reset
cross-check caught a hand-computed wrong mstatus reset in the document while it was being
written. Slice (c2) recorded the flip-bound rule: a tracked generated module needs a
tracked canonical input, so the rv64gc modules land with the descriptor at the flip.

Slice (d): the engine learned the machinery. `semulith-core`'s new `privilege` module owns
trap delivery (delegation, the privilege stack, the trap record, pc←xtvec), `xret`, the

generated rv64gc modules and the tracked machinery — the CSR disciplines, trap delivery

Slice (e): the unit's documents grew to the flip's shape. The instruction census is the
