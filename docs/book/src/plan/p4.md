# P4 — the Linux CPU profile

**Deliverable: the processor Linux actually needs, validated as a processor.**

Select a Linux-capable profile — provisionally RV64GC with an explicitly chosen privilege
revision, M/S/U modes, Sv39 translation, implemented CSRs, interrupt acceptance, counter
behaviour, and stated firmware and toolchain requirements. *Provisionally* is load-bearing:
the exact dependency closure is resolved before the profile is claimed, not assumed from the
letters.

## The new work

System transitions, page walks and their permitted side effects, protection, atomics, floating
point, instruction visibility, faults, and restart obligations — all implemented and
independently tested **in the laboratory environment**, not by booting something and seeing
whether it complains.

## The floating-point condition

Floating-point support is not included until a named Rust implementation has passed its own
qualification task: the exact target policy for rounding modes, flags, result bits,
conversions, NaN payloads and boxing; the ancestry inventory (shared SoftFloat lineage, target
specialization, thread-local versus global status handling, exact compiler and features); and
independent numeric fixtures.

If no suitable Rust implementation passes, the required subset is implemented in Rust and the
corresponding CPU capability is deferred until validated. There is **no silent native-float or
FFI fallback** — that would make the host's floating-point defaults into the guest's semantics.

## Sv39 translation and protection: `.3` underway (slices a–d, 2026-10-04)

Slice (b): the translation machinery shell lands — a `translation.rs` beside

Slice (c): the walk itself is live — the ten steps of §11.1.3.2 cited one by one

Slice (d): the cache gets real. A minimal fully-specified TLB — 4 entries,
fully-associative, FIFO, ASID-tagged, keyed by 4 KiB page — sits between the access

satp's mode and ASID changes visible immediately, staleness legal until a fence and

census carries the cache's parameters as data, and the generator refuses a document

both engines, all 62 guests.

Slice (e), part 1: the walk stops being a unit-test promise and becomes a corpus.

## Interrupts, counters and wait: `.5` landed and closed (slices a–d, 2026-10-05)

The design brief (a declared virtual-time domain, pending evaluation at the step
head, a real halt with WFI's spec wake, the M-source bits staying read-only 0)
executes in four checkpoints. Slice (a): time moves. The laboratory's virtual-time
domain advances one tick per step boundary, retired or halted — a pure function of
the step index, so determinism and EVD-05's exact values hold by construction. The
storage is ONE domain: `mcycle` holds it, `time` views it (the spec's own "a valid
implementation of RDTIME"), and `minstret` counts genuinely — a trap-delivered,
reserved or halted step never increments. The rate and the count rule are data in
the state document. The moving counters exposed a latent defect — a field-less CSR
view masked to zero, so the counter views would have read 0 forever — fixed at
root as a full-width shadow. mm-counters, the only counter-reading guest of all
88, re-derives five cells by design (time at executed step k is k); the other 87
guests run byte-identical against the parent engine.

Slice (b): interrupts fire. Every step head evaluates pending — the (a)(b)(c)
taken-rule, the global enables, the delegation mask, the fixed priorities with
the M-source bits read-only 0 — and delivery honors both xtvec.MODEs (the
synchronous trap keeps BASE; the vectored interrupt rides BASE + 4×cause) with
the Interrupt-bit cause, the un-fetched xepc and the xPIE/xIE/xPP stack. Seven
i-* guests carry the evidence: the taken-rule per mode, the enable immediacy,
the timer across the ticking domain, the delegation mask, the priority drain,
both vector modes, and a nested delivery's stack restoration — 95/95 through
the corpus, all 88 pre-slice guests byte-identical (the census proved none
could become eligible).

Slice (c): the acceptance's machinery. A legal WFI now halts the hart — one
ACTIVE/WAITING bit, cold-ACTIVE at reset, declared in the state document's
SEM-08 census like the TLB and the reservation before it. A halted step retires
nothing and issues no fetch, but the domain ticks: time passes while nothing
executes. The wake is the spec's own condition — a locally-enabled pending
interrupt at any privilege, regardless of the global enables and of mideleg —
and the taken-rule decides what happens next: the timer's arrival delivers the
trap with xepc = the WFI's pc + 4, or execution simply continues. The
expectations vocabulary gains the `<halted>` pseudo-step. Four wake guests
carry the family — the timer wake with its rdinstret reading 11 at the handler
(the leaf's acceptance, observed), the wake-without-trap idle loop, the
delegated source that wakes an M-mode hart anyway, the software-posted sources
with the globals off — and mm-wfi re-derives around arranged wakes with its
trap cells measured unchanged: 99/99 through the corpus, 94 pre-slice guests
byte-identical.

Slice (d): the matched attempt and the leaf's acceptance. Against the matched
Sail configuration (the override materialized fresh, validate-config clean, no
change needed), the software-posted-bit cells match exactly — six guests AGREE
(i-accept, i-deleg, i-enable, i-nest, i-vector, w-sw; 218 steps, with Sail
numbering the interrupt-delivery step and printing no row, the same convention
the laboratory declares). The six named divergences are all platform-shaped,
never semantic: Sail's timer block gates on `plat_have_clint`, so STIP never
sets without a CLINT (i-prio, i-timer); Sail's WFI is a nop under the matched
platform, so the real halt has no counterpart (the four `<halted>`-step
guests); and mm-wfi's TW cell is the named gap, freshly measured — Sail never
judges TW under the matched config, and with the wait modeled the delivered
trap is identical (cause 2, mepc = the wfi's pc, xtval = the wfi's word),
30/30. The `.4` corpus re-run under the fresh override reproduces its 11 AGREE
+ 1 named of 12 exactly — verdict-neutral. The leaf's criterion closes on
w-timer's own run: three boundaries with no register observation (the two
`<halted>` steps and the delivery), then the handler's first read —
rdinstret = 11, nothing retired across the halt — and the timer trap with
mepc = the WFI's pc + 4. The wake occurred without CPU retirement: the
laboratory makes time pass while nothing executes.
