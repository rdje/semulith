# P5–P7 — board, Linux, computer

## P5 — model one board in Rust

A minimal virtual platform with documented memory, reset, timers, interrupt controllers, and a
serial console. Each device gets a dossier, requirement and evidence links, and state, reset,
and access tests — devices reuse the same machinery as the CPU, they are not a lower tier.

The composition obligation is the interesting one: **for every CPU assumption, identify the
board or device guarantee that satisfies it, or reject the composition.** Reset wiring, memory
attributes, source priorities, counter units, time progress, access side effects, reservation
invalidations, instruction visibility. A model mismatch found later becomes a CPU, contract,
device, or composition issue with explicit ownership — never an unattributed "emulator bug".

Address maps, wiring, and hardware-description data are generated from the canonical board
definition. Device behaviour stays owned by the device definition.

**Gate BOARD:** devices and composition pass their applicable gates; small firmware probes
pass; no silently incompatible CPU/environment assumption remains.

### The first board, specified: `netboard-lab-v0` (EXPERIMENTAL)

The platform specification is done (`P5-BOARD.1`, `2026-10-02`): the canonical definition is
`profiles/netboard-lab-v0/board.sexp`, gated by `schema/board.sexp` and narrated by the
dossier's `DOSSIER.md`. It composes `rv64i-lab-v0` v0 — the EXPERIMENTAL CPU release, whose
status the board inherits — with exactly two devices, and it **pins versions, not names**:
the processor by unit id + version + the GATE-REPORT-gated dossier content digest, each
device by its datasheet's material id + revision + sha256.

- **Memory map:** 2 GiB RAM at `0x8000_0000` (the laboratory harness's existing base, so
  laboratory guests run unchanged); the SiFive UART at `0x1001_0000` (the sourced FU540-C000
  instance address); the LAN9118 NIC in a 256-byte window at `0x1002_0000` (the datasheet's
  direct-register span). Fetch is served from RAM only — every MMIO region is declared
  non-executable, so no fetch can have a side effect.
- **Reset:** cold only; the entry state is the CPU contract's, cited not restated.
- **Timers and interrupt controllers are absent by contract** — declared as data with the
  obligations the absences satisfy (`OB-ENV-VIRTUAL-TIME`, `OB-ENV-EVENT-DELIVERY`). A
  CLINT/PLIC would be a composition rejection, not a feature; both devices' interrupt lines
  are unconnected and declared so, and drivers poll.
- **The network device is the board's window on the world from v0:** the LAN9118 is
  programmed-I/O (no bus-master DMA), so every device effect reaches the guest through its
  own MMIO accesses. Receive is recorded-trace replay (deterministic, evidence-grade);
  transmit is a recording sink; a live host socket stays laboratory play, never evidence.

One measured correction landed with the specification: the serial device is the **SiFive
UART** of FU540-C000 §13, not a 16550 — the earlier label survived a design brief and was
measured false against the pinned PDF (zero occurrences of "16550" in the document) before
it could ossify into a device dossier. The source pin, not the label, was the intent.

Device dossiers (`.2`), generated maps and the composition manifest (`.3`), and the
composition verdict against every CPU assumption (`.4`) follow; the board unit's
registration and book land with the materialization leaf (`.3`).

### The archogen branch

At this point a compatible archogen-generated OS may enter its own integration gate without
waiting for Linux or the full computer. Its required CPU profile must already have passed a CPU
gate; if it needs fewer features than P4, a separately accepted smaller profile can support an
earlier board branch under the same rule.

## P6 — boot Linux to useful userspace

Pin the firmware, the kernel, the build configuration, the hardware description, and the
initramfs. The default RISC-V route executes compatible M-mode firmware providing selected SBI
services before entering an S-mode kernel. A host-modelled SBI is a *different contract* and is
never silently substituted for it.

**Gate LINUX:** a reproducible cold boot reaches userspace `init` and a console shell, runs a
guest program, exercises timer-driven scheduling, and completes a documented shutdown or reboot
path. A kernel banner is not a pass.

CPU bugs discovered here return to CPU regressions and **invalidate affected evidence**. Booting
does not retroactively prove the CPU; failing to boot does prove something was wrong.

## P7 — a useful headless computer

Persistent block storage, file workloads, networking, reset and reboot, and system snapshots —
each as an individually specified increment with reproducible guest workloads and device
evidence.

**Gate SYSTEM:** the declared headless workload suite passes, storage persists correctly, and
snapshot/restore preserves the relevant CPU, device, and event state. This is the first bounded
full-computer release.

Graphics, input, and a desktop are a **subsequent** product increment with their own device list
and performance budget — kept visible rather than hidden inside P7.
