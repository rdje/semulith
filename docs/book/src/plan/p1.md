# P1 — the processor laboratory

**Deliverable: a machine that can execute a small slice, and machinery that can tell the truth
about it.**

## The crates

Three initial Rust crates, with the ownership boundary stated up front:

| Crate | Owns | Must not |
| --- | --- | --- |
| `semulith-core` | profiles, typed values, generated state, decode, semantics, the definitional interpreter that evaluates them, the environment request/response contract, execution control | depend on the CLI or the verification harness |
| `semulith-verify` | controlled memory and event fixtures, the source/evidence graph, adapters, comparators, the reducer | supply production instruction semantics |
| `semulith-cli` | user commands and report presentation | duplicate behaviour that belongs to the other two |

The skeleton stands since `P1-LAB.1`: the crates exist, `cargo tree` shows the one-directional
edges (`cli → {core, verify}`, `verify → core`, `core →` nothing), and the workspace builds for
the host **and** for `wasm32-unknown-unknown` — the browser is a first-class target from the
first crate, enforced by the `PORT-WEB` doctrine on every commit, not promised for later
(`decision_browser-wasm-target`).

## Target arithmetic, stated per operation

The first real content is `semulith-core::arith` (`P1-LAB.2`). SEM-03's rule is that every
numeric operation states its widths, signedness, intermediate precision, truncation, and
exceptional behavior **in its own contract** — never inherited from host defaults — and each
function carries its source link: the requirement record in `requirements.sexp` and the
pinned locator that requirement was derived from. Target values are held in `u64`;
signedness is a per-operation contract, not a type. The shift-amount masks of REQ-D-SHAMT live
in two functions (`shamt64`, `shamt32`), and an unmasked amount reaching a shift panics in
debug rather than silently wrapping — a decoder bug must not masquerade as a plausible result.

The verification is worth imitating: boundary cases at full XLEN, an **exhaustive 8-bit
layer** over every input pair against references written on a different host width
(multiplication-as-shift, De Morgan formulations), and a boundary-heavy sweep of the word
operations. The exhaustive layer caught a real trap on its first run — signed comparison and
arithmetic shift are *width-sensitive*, so a reduced-width check must sign-extend its inputs
to the target width before comparing — which is now a knowledge card
(`docs/knowledge/reduced-width-verification-of-signed-ops.md`). Host-mode consistency is
verified there, not assumed.

## Architectural state, generated from the descriptor

`semulith-core::state` (`P1-LAB.3`) is not written by hand. `scripts/gen_state.py` derives
`state.rs` from the profile's `state.sexp` — the descriptor is the authority
(`docs/ARCHITECTURE.md` §2), the module is its mirror, and the `STATE-GEN` doctrine refuses
the day the two drift: regeneration is `python3 scripts/gen_state.py`, never an editor, and
the descriptor's sha256 rides in the module header so the exact input bytes are named. The
generator is deliberately narrow — an unfamiliar shape (another profile, a non-64 width, a
special register it has no mapping for, a missing SEM-08 census) is **refused by name**,
because a generator that guesses is a second definition wearing the first one's clothes.

The state itself is one fixed-width storage: 32 × 64-bit integer registers and the program
counter — 264 bytes inline, no heap, no per-access allocation (RUST-03). x0 is hardwired to
zero: a write is discarded, a read yields 0. The three roles the ISA chapter itself names —
x1 the return address for a call, x2 the stack pointer, x5 the alternate link register — are
emitted as alias constants, and an alias is a *view*: a value written through one name is
visible through every other, which is catalog C02's question ("does writing one alias
correctly affect every other view?") answered in code and held there by tests. Reset is the
laboratory declaration of REQ-D-ENTRY-STATE: x1..x31 = 0 (the base ISA leaves initial
contents to the execution environment), pc = the entry address the environment supplies.

SEM-08's hidden-state census rides along as data. This profile checks seven candidates —
CSRs, the LR/SC reservation, floating-point state, vector state, privilege and trap state,
fetch-cache state, partially committed effects — and answers *none present*, which is why
snapshot and replay will honestly reduce to registers, pc, and memory (P1-LAB.10). Every
extension added later reopens the census; the state module regenerates with it.

## The environment boundary

`P1-LAB.4` draws the line the CPU crosses. `semulith-core::env` owns the contract types:
requests (fetch, load, store), success responses, and two failure families kept apart on
purpose. `Failure` is target-facing — access fault outside a declared region, misaligned per
this profile's no-invisible-misalignment rule — and the instruction layer will convert it
into a typed target outcome. `ContractViolation` is the environment breaking a rule — a
harness-side report, never a target exception. That distinction, in types at the boundary,
is SEM-01's separation arriving before the full outcome families do (`.5`).

The width set is pinned by construction: fetch carries no width at all (always 32 bits),
and loads/stores accept only 8/16/32/64 — a request the contract does not offer cannot be
formed, which is stronger than refusing one. Loads return raw bits; extension into XLEN is
the instruction layer's rule, not the boundary's (REQ-D-LOAD-EXT). Addresses are bare
`u64`s — no host pointer ever stands in for a guest address (SEM-05).

`semulith-verify::fixtures` implements the contract for tests. `FlatMemory` is the
laboratory platform's one region: little-endian main memory, no side effects, re-read on
every fetch so a store to a later-fetched address is visible immediately (a legal choice,
not an architectural guarantee — a caching reference is equally correct without Zifencei),
answering misaligned and out-of-region accesses with the specified failures and counting
every fetch it serves. `ScriptedEnv` pins a whole conversation in advance — faults
scriptable as environment answers — and when a request arrives that the script does not
cover, it reports a contract violation instead of inventing data
(`docs/CPU_ENVIRONMENT.md` §4.1.4). The whole boundary is testable with no instruction
handler in sight; the acceptance, and the laboratory's first working instruments.

## What "laboratory" means

Controlled memory responses, fault and event injection, deterministic stepping, explicit
outcome types, and input replay. It is deliberately **not** a board: a board models real
devices and comes after the CPU gate. The laboratory's job is to be able to answer *"what does
the CPU do when the environment does exactly this?"* without a device implementation standing
in the way.

## Four typed outcome families

A single error type is the most common way an emulator loses the distinction that matters.
`semulith-core::outcome` (`P1-LAB.5`) keeps SEM-01's families apart as types, and nothing
converts between them:

- `TargetEvent` — something the *target* did under a named source rule: `Exception` (the
  unprivileged cause vocabulary, each cause named by the rule that raises it) or
  `RequestedTrap` (ECALL/EBREAK). Delivery is a data event, not a stop command — OB-ENV-EVENT-
  DELIVERY pins it to the instruction that raised the condition, and REQ-D-ECALL-EBREAK says
  execution stops *unless the harness contract says otherwise*. The harness receives the
  event and decides; a test proves an exception can be delivered and the very next
  instruction still run.
- `Advance` — progress: `Completed`, or `Stop` with a reason. There is no waiting and no
  partial advance in this profile, and those absences are platform facts (OB-ENV-VIRTUAL-TIME,
  OB-ENV-PARTIAL-PROGRESS) recorded so a future extension reopens them in the type, not
  around it.
- `ModelError` — the model or harness is wrong: `Unimplemented`, `InvalidDescription`,
  `InconsistentState`, or a harness `ContractViolation` (`.4`'s boundary-local violation
  family, re-homed). SEM-02's rule is structural: an unimplemented instruction is a
  `ModelError`, and "report it as an illegal-instruction trap" has no typed expression.
- `UndefinedCase` — a source-classified unspecified/reserved case, carried as its own
  outcome under the run's diagnostic policy. REQ-D-RESERVED-DECODE requires the model to be
  able to say the case *was* unspecified; this family exists so that report never has to
  disguise itself as an exception. Conversion is the policy's explicit act, and it must
  stay able to say why.

A step of execution returns `StepOutcome`, one of the four; the interpreter (`.8`)
produces it and the harness matches on it. Types alone cannot prove a developer picked the
right variant — which is why the validator mutation suite exists (`.9`).

## The canonical definition, generated

The definition the gates check is one thing; the definition an engine executes must be the
same thing, lowered. `P1-LAB.6` closes that gap: `scripts/gen_definition.py` generates
`semulith-core::definition` from the unit's encoding composition and the semantics data —
byte-deterministically, formatter-stable, and with a drift doctrine (`DEF-GEN`) that fires
the day the module and the definition part ways.

What the module carries, all lowered, none handwritten:

- `FIELDS` — the twelve operand fields, with the B/J immediates' scatter pieces attached, so
  a decoder can unscramble them from the same table it extracts with.
- `INSNS` — the 52 instructions, sorted: fixed-bit `mask`/`value`, declared operands, the
  upstream encoding table each came from, and the specification locator its semantics cite.
- `Sem` — every semantics rule's effect tree as typed data. This is the shape of the
  execution-authority decision (`decision_interpreter-before-compiler`): the semantics DATA
  owns each rule (OWN-01), the interpreter (`.8`) evaluates exactly these trees, and there is
  no handwritten second copy of any rule anywhere.
- `decode(word)` — fixed-bit dispatch: a word matches an entry iff `word & mask == value`;
  no match is the reserved-decode case, and classifying it is the caller's job, not the
  table's.
- `MANIFEST` — OWN-03's generation manifest as data: every canonical input by
  repository-relative path and sha256, the generator named and content-hashed, the
  configuration (profile, ilen, composed fragments) carried as data, and the upstream source
  fingerprints the fragment pins. A reviewer can name the exact bytes — and the exact
  generator — behind every row.

The generator earns "generated" the hard way: it re-derives, per input, the schema layer's
validation, the SEMANTICS binding rule (a split store immediate reads as one `imm12`, a
branch as one `bimm12`, either shift field as `shamt`), the MODEL-COMPOSE.6 refinement rule,
and completeness — and refuses by name what it cannot emit: another unit, an unsupported
instruction length, an instruction without semantics, an operand the encoding does not
provide, a missing semantics document, a width that is not stated literally. Two details
worth imitating. FENCE declares `fm`/`pred`/`succ` as operands with no field ranges; the
module says so instead of inventing ranges, and a test ratchet names the three decorations
so a fourth unfielded operand fails loudly until someone dispositions it. And the effect
trees are emitted fully broken one level per line — the generator's shape and rustfmt's
agree, so the drift gate compares content, never formatting.

Ten Rust suites re-derive the generation-time invariants on the emitted data: manifest
completeness, alphabetical completeness, fixed-bit disjointness (no word decodes to two
instructions), every instruction matching its own fixed bits, scatter accounting, the
binding rule, the citation rule. A hand edit now fails twice — in `cargo test` and in the
`DEF-GEN` gate — which is the point: a mirror with one guard is a hope; a mirror with two
is a derivation.

## The graph and report checker

`P1-LAB.7` builds the other half of the evidence machinery: the checker that decides
whether the record files *mean* anything. The frozen `examples/` records had been validated
by a tracked Python JSON Schema validator — but the planning package's check results ("all
5 records validate", "all 6 negative controls rejected", "the synthetic source fingerprint
matches") lived in a delivered document, cited rather than re-derived. That gap is now
closed in Rust (rule RUST-01), in `semulith-verify`, which owns the source/evidence graph
per the architecture's crate map and carries no dependencies — so the reader, the pattern
engine, and SHA-256 are all this project's own, each refusing by name what it cannot do.

Two phases, both runnable as `semulith check-examples` and wired into the `RECORD-SCHEMA`
gate so they re-run on every commit. Phase one validates every record against its schema
with a validator that implements exactly the keyword subset the three schemas use and
refuses anything else — a schema gaining power breaks the gate loudly. Phase two checks the
graph the schema cannot see: identifier references (orphaned evidence, deleted dependency
links), profile-scope consistency, duplicate and cyclic requirement identities, citations
against the pinned source ledger, artifact existence and hashes (a stale hash is named as
such), every declared obligation pointed at by at least one evidence record, and a gate
verdict — `passed`, `incomplete`, or `failed` — computed only from successful, current,
hash-verified evidence.

The verdict honesty is the design. The fixture's evidence is deliberately `planned`, so the
checker's report on the intact bundle reads `gate: incomplete — no graph defects, but 2
declared obligation(s) lack successful current evidence` and exits zero: incomplete is the
truth, not a failure. A bundle with a fabricated link, a stale hash, or an unsupported
`passed` claim exits one with each finding named. The mutation suites prove both directions
— one mutation per designated wrong behaviour, each caught.

## The first execution slice

`P1-LAB.8` is the moment the definition executes: `semulith-core::exec`, the definitional
interpreter, evaluates the semantics-data effect trees `.6` lowered — the data stays the one
executable owner of every rule (OWN-01), and the interpreter is its evaluator, not a second
implementation. One step fetches through the environment contract, decodes, extracts the
operands (scattered B/J immediates unscrambled per the field piece tables, split fields
bound per the semantics rule), and evaluates the tree — with an explicit width on every
value, because the semantics file's own rule is that widths are explicit: `sext`/`zext`
extend *from the operand's own width*, which is what makes `(sext 64 (shl (imm imm20) (lit
12)))` the LUI sign-extension from bit 31 and `(sext 64 (load (lit 8) …))` the LB extension
from 8. The reporting rules land exactly where the profile pins them: a misaligned branch
target raises on the branch (REQ-D-MISALIGN-REPORT), a fetch fault reports at the pc
(REQ-D-FETCH-FAULT-REPORT), a misaligned load raises before the boundary is crossed
(D-MISALIGN-DATA), reserved decode is reported as the unspecified case it is
(D-RESERVED-DECODE), and ECALL/EBREAK are requested traps, never exceptions
(REQ-D-ECALL-EBREAK).

`semulith-verify` owns the observation layer: a step is `(pc, word, register writes, trap)`
— the same normalized vocabulary `scripts/compare_traces.py` had already reduced the
reference models to — and the first-divergence comparator walks two traces and names the
first differing observation (a register, the trap cause, the tval), or reports a length
mismatch as a non-agreement. A shorter trace is never a pass.

The guests are the four tracked programs, assembled from the profile's `.s` sources with the
tracked assembler, executed under the laboratory's `FlatMemory` — and the expectations they
are checked against were derived from the pinned specification prose before any model ran
(EVD-05). The fixture is generated (`scripts/gen_guests.py` → `semulith-verify/src/guests.rs`,
the 23rd doctrine `GUEST-GEN` refuses drift), so the commit gate re-runs the whole slice
offline: state observations for `smoke-arith` (twelve steps, every value checked), control
flow for `guest-control` (thirteen steps from twelve instructions, with the negative
`never_written` registers a failed jump would expose), the misaligned-load trap for
`smoke-trap`, and the no-device access fault for `guest-no-device`. The live experiment,
`scripts/run_semulith_smoke.py`, then runs the same guests on the pinned references: on
`2026-09-28` semulith agreed with sail-riscv and spike on every enabled comparison —
34 aligned steps across the four guests, each run reproducing byte for byte. Finite
differential testing is tested evidence, never universal proof — but the first slice now
stands on evidence, not on the definition's say-so.

## Validating the validator

`P1-LAB.9` answers the uncomfortable question about everything `.8` proved: the differential had
only ever *agreed* — and a comparator that has never disagreed is not known to detect anything.
EVD-09 demands a mutation suite: intentional wrong behaviour that must be caught.

The seam is one parameter, not a parallel implementation. `exec::step_over` and `run::run_over`
take the instruction table, and production passes the generated `INSNS` — so a mutated model is
*data the one evaluator consumes*, which keeps OWN-01 intact: the suite perturbs trees and
decode rows, it never writes a second semantics. The wrong behaviours it runs, each detected at
its designated step with the differing field named: a zero-extension in place of addi's
sign-extension (x1, step 1); jal's link write suppressed (x5, step 7); ebreak's cause read as
11 instead of 3 (the trap cause, step 0); a model limitation dressed as an IllegalInstruction
trap — SEM-02's exact violation, caught against the full model at step 0; a phantom load added
to every addi, invisible to the architectural trace and caught only by the boundary-crossing
census; a trap deferred one step, caught at its due step; srai's decode mask widened so srli's
word silently executes as srai (the changed defined bit no longer discriminates); a reference
run at a stale entry, caught at step 0. And the arm the `guest-control` expectations name: jalr
keeping its odd target bit — the fault at `0x80000029` both reference models can never show,
because both clear the bit. A comparison-suppression exhibit closes the loop: a comparator
blind to register writes *agrees* with a mutant the real comparator catches, which is why the
writes leg is not optional.

Every guest arm first re-derives the pinned expectations against the real model, so the anchor
cannot drift silently either. The suite is the detector's proof, not the model's: coverage is
the arms, not the space — and new semantics land with new arms beside them.

## Replay and reduction

`P1-LAB.10` turns a result into an artifact. A divergence the differential caught used to exist
only as a test's in-memory value; gate `G1`'s first criterion is that **failures are replayable
from recorded inputs**, and `docs/ARCHITECTURE.md` §7 states what a seed must carry to mean
anything: code and generator versions, initial state, guest image, environment policy, and the
relevant event choices — *a seed without the generator version and event stream is insufficient*.

`semulith bundle --guest=guest-control --mutate=zext-addi > case.json` records exactly those.
The bundle's `algorithm` block flattens the definition's own `MANIFEST` — profile, instruction
length, the generator named and content-hashed, every canonical input pinned by path and
sha256 — and adds the harness version and the model under test (`production`, or `mutant:<name>`
from the `.9` vocabulary). Around it: the platform's memory region, the entry address, the
guest image with a sha256 guard, the step budget, and the recorded result — every observation
step plus the stop. The event choice is recorded as data, not left implicit: this platform
declares no asynchronous event (`OB-ENV-EVENT-DELIVERY`), and the bundle says so.

`semulith replay case.json` re-derives the result from the recorded inputs. Identity is checked
before execution and by name — a definition pin that no longer matches the live manifest, or an
image whose words no longer hash to the recorded digest, is refused with the pin named, because
replaying against different definitions is a different experiment, not a replay. Then the
recorded and re-derived traces walk together through the first-divergence comparator, so a
drifted result is named at its first differing observation, never summarised away. A bundle
missing any accompaniment fails to parse naming the field — the bare-seed refusal is
structural, not a policy a reader could waive.

`semulith reduce --guest=guest-control --mutate=jalr-odd-bit` is the other half — EVD-02's
minimized discrepancy. The input domain is the guest's word sequence (one instruction is one
observation step at this profile's ILEN of 32), the property is the differential's own, and
**retention is the original first divergence exactly**: same step, same field. That sounds
stricter than it is — a same-step retained divergence is byte-identical, because the executed
prefix is unchanged — and the strictness is the point: a reduction that merely shifts the
symptom is a different bug wearing the original's clothes. The search is classic delta
debugging, and every accepted removal preserves the property by construction, so the result
always retains; the suite proves minimality the honest way, by attempting every single-word
deletion of each result and showing none retains. The jalr odd-bit case reduces from twelve
words to nine — the two instructions behind the misaligned jump are never reached by the
first-divergence walk — and the retained trap is still `InstructionAddressMisaligned` at
`0x80000029`, the fault the fixture note predicted.

One boundary is named, not papered over: a wrong behaviour the observation vocabulary cannot
see is not reducible on observations. The phantom-load mutant keeps the architectural trace
intact — only the boundary-crossing census sees its extra access — so the reducer refuses it
with `NoDivergence`, and the census owns that class. A detector is allowed to have named
jurisdiction; what it may not do is silently extend it.

## The laboratory bench

`LAB-BENCH.1` is the surface you can touch while the rest is being built. `semulith demo
--guest=guest-control --mutate=jalr-odd-bit` runs a tracked guest under the definitional
interpreter — or under one of the validator suite's mutations — and prints every observation:
pc, instruction, register writes, traps, and then the judgement. The exit code is the
detector's verdict: 0 when the pinned expectations hold, 1 when a designated mutant broke
them — the tool disagreeing with a broken model on purpose, so a caught mutant reads as
success, not failure.

The browser bench is the same run with buttons. `make bench` compiles the verify crate's
`cdylib` for wasm — the exports are std-only `extern "C"`, no wasm-bindgen, no new
dependency — and `bench/index.html` renders the clean and mutated traces side by side with
the first divergence highlighted. Flip the model to `phantom-load` and the page tells the
census story the trace cannot: the architectural observations still agree; the boundary
crossings do not. `scripts/smoke_bench.js` verifies the page's engine headlessly with node,
so the bench is gated like everything else even though no browser runs in CI.

## The performance baseline

`P1-LAB.11` measures the laboratory instead of guessing about it. `semulith bench` runs four
workload mixes — **arithmetic** (the ALU vocabulary, no memory traffic), **control**
(alternating taken/not-taken branches plus jal/jalr call-return), **memory** (stores and
loads at all four widths), and **fault** (a model-side misaligned load, a model-side
misaligned store, and an environment-side out-of-region load on every iteration) — in the
three modes the architecture demands: **untraced** (the bare `exec::step` loop, no
observation constructed), **instrumented** (the `(pc, word, writes, trap)` observation
stream), and **diagnostic** (the stream plus the full boundary-crossing log). Each mix is a
generated counted loop ending in EBREAK; every generated word is pinned to the instruction
the generated definition decodes it to, so the harness can never drift from what it
measures. Tracing is checked, not trusted (RUST-02): all modes must agree on step count,
stop, final architectural state and the crossing census, and every recorded stream must be
identical — a disagreement is a refusal, not a footnote.

Measured on a **named host** (Apple M4 Pro; Darwin 27.0.0; rustc 1.95.0, release profile;
iterations=10000, 2 warmups, 12 repetitions per cell — the command above re-derives every
number):

| Mix | Steps | Untraced | Instrumented | Diagnostic | Allocs/step (untraced → traced) |
| --- | --- | --- | --- | --- | --- |
| arithmetic | 280,003 | 52.1 ns | 69.6 ns | 73.4 ns | 1.00 → 1.19 |
| control | 95,004 | 47.2 ns | 65.4 ns | 70.1 ns | 1.00 → 1.42 |
| memory | 170,006 | 54.1 ns | 71.0 ns | 76.9 ns | 1.00 → 1.23 |
| fault | 50,010 | 50.9 ns | 69.4 ns | 71.0 ns | 1.00 → 1.20 |

The per-cell noise spread ((max−min)/median over 12 repetitions) was 1.7–7.4%, with one
scheduler outlier at 113% on a millisecond-scale cell. **No regression threshold is set**:
RUST-04 requires the noise to be characterized first, and this table is what a future
threshold must cite — a threshold invented before the noise is known is either never
triggered or always triggered. There is no universal MIPS target, and these numbers predict
nothing about Linux boot speed.

Two long-parked questions resolved by measurement. The diagnostic observer's dispatch:
static generics versus a trait object measured ×0.974–1.002 across the mixes — within the
cells' own noise — so static stays the default and a trait object is permitted where
extensibility needs it; the "zero-cost" assumption is now a measured fact. And RUST-03's
"no mandatory per-instruction allocation" is a number instead of a posture: the interpreter
allocates exactly one Vec per step (operand extraction), 1.00 allocation and ~127–141 bytes
per step untraced — a measured departure, on record for the milestone that needs it.

## Gate G1

Failures are replayable; model limitations differ from target traps; malformed evidence links
are rejected; known validator mutations are detected; the measured baseline is recorded; and a
compiled freestanding guest retires under first-divergence comparison against a pinned
reference.

`P1-LAB.12` lands the report itself: `profiles/rv64i-lab-v0/G1-REPORT.md`, generated by
`scripts/gate_report.py --gate G1` from tracked inputs only — never hand-written, and
regenerating byte-identically in a fresh clone (the `GATE-REPORT` doctrine fails the commit
otherwise). Each criterion's standing is measured from tracked artifacts by concrete name: the
replay/reduce machinery and its CLI wiring, the four outcome families and the SEM-02 arm, the
graph checker, the mutation suite's arm count re-derived from its test module, the recorded
baseline (`baseline.sexp`), and the guest census. The generator has no code path to `passed`
while a criterion stands unmet — the EVD-08 rule, generalized.

The verdict today is **`incomplete`**, and the report names why: five of six criteria are met;
criterion 6 — the roadmap's "compiled freestanding guest, C is the first guest path" — stands
unmet as written. The four tracked guests are freestanding programs that retire under
first-divergence comparison against sail-riscv and spike (34/34 aligned steps), but they are
assembled by the project's own tracked assembler, and no C-toolchain guest exists yet. That
gap is owned by `P2-SCALAR.5`. This mirrors G0's precedent exactly: the milestone's leaves
complete; the gate's verdict stays honest.
