# P3 — breadth, and the DSP pressure

**Deliverable: an abstraction that has been pushed on by something that is not a scalar CPU —
and an honest statement of what that proved.**

## Why now and not later

A cross-architecture API stabilised against one scalar CPU encodes that CPU's assumptions as if
they were universal: uniform operand widths, a single address space, instruction-level
atomicity, results visible at the end of the instruction. Real DSPs break all four. Discovering
that after the API is published means either a breaking change or a permanent workaround.

## What is actually done

1. **Review 15–20 discriminating cases** from real DSP specifications, chosen for properties
   those processors genuinely have — accumulator and guard widths, fractional scaling, where
   rounding happens relative to accumulation and narrowing, sticky flags across interrupts,
   instruction versus data address units, modulo and bit-reversed addressing, issue-group
   operand visibility, delayed results, hardware loops interacting with interrupts. **Done**
   (`DSP-REVIEW` 8/8): six interface findings routed into this milestone, each with routing
   evidence; none reproduces on the scalar profile.
2. **Add executable synthetic tests** for nonstandard widths, distinct address spaces, packets,
   delayed effects, and register grouping. **Done**: the five-probe synth suite measures the
   pipeline's refusals by name (grouping probe added when a finding lacked an executable
   demonstration).
3. **Select a narrow real DSP slice** only after demonstrating its evidence path — or publish a
   deliberately limited experimental claim instead. **Path demonstrated and slice selected**
   (`2026-10-01`): the oracle census measured TI C6000 absent (no pinnable executor),
   DSP56300 strong (MIT assembler + MIT silicon-validated emulator), SHARC partial; the
   DSP56300 path was exercised end-to-end here (pin, build, micro guest, three-way verified
   dump). The bounded subset is `dsp56300-lab-v0` v0 — non-parallel moves with the A2/B2
   extension readout, the immediate/register ALU core, signed `mpy`/`mac`,
   `nop/jmp/jsr/rts`, `do`/`enddo`/`rep`, linear addressing — every exclusion named against
   the reference's documented gaps, implemented as an EXPERIMENTAL sibling crate and
   evidenced as canonical end-state equality against the pinned emulator's difftest.
   **The subset is form-complete and agreed** (`2026-10-01`): the ALU core
   (add/sub/cmp/and/or/eor, asr/lsr), jsr/rts, rep/enddo and the seven linear (Rn) modes
   landed with per-form FM citations, and six synthetic guests AGREE 6/6 over the
   canonical end-state dumps (51–64 fields per case, `cyc` excluded by rule). The
   campaign measured five places where naive FM readings diverge from the
   silicon-validated reference (RTS pulls PC only; short immediates sign-extend into A2;
   A1/B1 read raw — the limiter is whole-accumulator-only; S sets on bus reads only) —
   each recorded in the crate's module docs. No compatibility claim: the corpus is
   synthetic and the verdicts are end-state equality on it. **Everything since is the
   landing of that agreement as a governed unit** (the blow-by-blow with its leaf ids is
   `docs/tasks/P3-BREADTH.md`): the hidden-state census re-ran for the profile (SEM-08's
   question over 14 candidates — its measured consequence: for subset v0 under its named
   exclusions, the canonical end-state dump *is* the complete architectural state, which
   is what makes snapshot and replay honest here); the schemas learned the DSP's shapes
   (register families with masked widths and per-part readouts, memory spaces, the
   hardware stack); the dossier landed under `profiles/dsp56300-lab-v0/` with every
   attaching gate green — the landing measured and fixed seven latent references.sexp
   defects no gate had been checking, and the gates now derive a unit's applicable
   contracts from its declared vehicle rather than presuming one evidence shape
   (`decision_gate-applicability-by-declared-vehicle`); the encoding/definition
   generalization was measured a lane, not an extension, and is deferred with named
   reopening conditions — the sibling crate remains the exercised, agreed vehicle; the
   contract records landed (seven requirements mirroring the decisions byte-identical,
   thirteen obligations as contract `dsp56300-lab-env-v0` with 26 declared checks,
   governed by RECORD-SCHEMA and FACT-OWNERSHIP exactly as the scalar profile's
   catalogues are); and the unit is registered (`materials/units.sexp`, the 24-row
   category-needs census beside it, SCOPE-COVERAGE green) with its own book building
   (`docs/models/dsp56300-lab-v0/` — UNIT-BOOKS, MATERIALS-BILL), the book generator
   having learned the sibling-crate shape so the declared vehicle drives what the bill
   emits.

## The honesty constraint

Synthetic behaviour tests the **interface**, not real DSP compatibility. A synthetic packet
fixture proves the API can express packets; it proves nothing about any manufacturer's part.

TI C64x/C64x+ is a *documentation* candidate. No runnable oracle access has been established,
and its availability is resolved before any compatibility release is promised.

## Gate BREADTH

The stated real subset has evidence; the public abstraction supports the exercised cases;
unsupported families remain unclaimed. A stable general API requires this gate —
architecture-specific CPU progress does not.

**The gate has RUN (`P3-BREADTH.6`, `2026-10-01`): verdict `passed`.** The capability
report is generated from pinned inputs — never edited — at
`docs/BREADTH-REPORT.md`, and the `GATE-REPORT` doctrine fails
the commit if it and its inputs disagree. Per axis, as the report measures them: the
stated real subset (`dsp56300-lab-v0` v0) carries its evidence anchors (the declared
scope, the guest corpus, the crate's commit-level tests, the recorded comparison
contract, the registered agreement mechanism); every abstraction construct the exercised
cases required is declared in its schema AND carried by the mapping owner, with the
refusal boundary pinned by five synthetic probes; and the unclaimed families are listed
explicitly — TI C6000 (survey verdict: no pinnable executor exists), ADI SHARC
(partial: a BSD-3 MAME core, no vendorable assembler), and everything else by omission,
because the unit registry is the complete claim list. What `passed` does not mean is in
the report: no stable-general-API claim beyond the exercised cases, no DSP56300 family
compatibility, no RISC-V conformance upgrade.
