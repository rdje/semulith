# P0 — profile and evidence access

**Deliverable: knowing exactly what we are modelling, and proving we can obtain expected
results for it.**

## The profile

Create `rv64i-lab-v0` as a *development* profile: RV64I semantics, one core, little-endian
ordinary memory, an explicit entry state, memory boundaries, an access and misalignment policy,
instruction-fetch rules, and environment-trap reporting. Pin the applicable specification
revision and resolve every choice the selected scope needs.

No privileged-system support is implied by any of that. Selecting RV64I is not a claim that the
laboratory already constitutes a fully specified privileged processor — it is the smallest
scope in which real scalar machinery can be validated at 64 bits without a 32-bit detour.

## The part that is easy to skip

Acquire reproducible source or binary builds for the chosen reference path, and **run at least
one actual matched-profile experiment before marking that reference usable**. Record tool
versions, source and binary hashes, effective configurations, adapters, and known gaps. Then
establish whether a second comparator shares relevant semantic code with the first.

That last sentence is the one that does the work. Two tools with different names are not two
opinions if their expected results come from the same model. Three facts already known:

- the RISC-V architectural tests use **ACT4**, which computes expected results with a
  *configured Sail* model — valuable external tests, not a second semantics;
- **TestFloat** ordinarily obtains its expected values from **SoftFloat**, so comparing against
  SoftFloat directly is not automatically another independent numerical engine;
- **Spike** is a different implementation path, but its subsystems' independence has to be
  examined rather than inferred from the project name.

## What acquisition actually found

That section was written as a plan. Here is what happened when it was executed.

**Three reference models were obtained and run on this host**, and one test corpus was located
and deliberately left alone:

| Candidate | How it was obtained | Configured to this profile by | Reports itself as |
| --- | --- | --- | --- |
| Sail RISC-V 0.14 | prebuilt `Mac-arm64` release binary | a tracked JSON override | `rv64i_zvl32b` |
| Spike 1.1.1-dev | source build, commit `1e05ddac` | `--isa=rv64i --priv=m` | `rv64i` |
| QEMU 11.1.1 | already on the host; used read-only | `-cpu rv64i` | *(emits no ISA string)* |
| ACT (`act4` branch) | reachable, not acquired | — | — |

**The budget was wrong in the project's favour.** The plan priced this work on building Sail
from source through an OCaml/opam toolchain, which is genuinely open-ended. Release 0.14
publishes a native binary for this host's exact architecture, so the model runs with no toolchain
at all. Sail turned out to be the *cheapest* candidate, not the most expensive one.

**One attempt failed, and the failure is the interesting one.** The host package manager has a
formula called `sail`. It is a CLI for deploying WordPress sites to DigitalOcean — an exact name
collision with the Sail ISA specification language. Identity was checked rather than assumed, and
the check is the only reason "Sail is available from the package manager" was not written down as
a fact. This is `SRC-03` earning its place: a candidate list is the easiest document in a project
to fill in from reputation.

### Three models is not three opinions

The plan already warned about this and the acquisition confirmed it in writing. ACT computes its
expected results using a *configured Sail model*, so ACT agreeing with Sail is one semantics
answering twice. Spike and QEMU were written independently of Sail and of each other — *plausibly*,
which is a hypothesis, not a finding. Every candidate record carries a `lineage` field stating
what is known and what is not, and the gate **refuses a candidate that omits it**, because an
independence question nobody asked reads exactly like one that was answered.

Resolving it per subsystem is a separate leaf. Having the binaries is not having the evidence.

### Two differences are already known, before a single instruction has run

The gate asks for profile and reference differences to be **enumerated, not assumed absent**. Two
turned up during configuration alone:

*The Sail model cannot be configured down to exactly "no extensions."* From a default of 96
supported extensions it reaches `rv64i_zvl32b` — the base plus a vestigial minimum vector-length
class that survives because the model always instantiates a `VLEN` even with the vector unit
disabled. No vector instruction decodes, so it is believed harmless. It is recorded anyway,
because "believed harmless" and "absent" are different words.

*The Sail model will not report the configuration it actually ran with.* Asking it to print its
configuration prints the **default**, ignoring the override — the two dumps are byte-identical.
The effective configuration is therefore *(default) + (our tracked override)*, and that merge is
**ours, not the model's account of itself**. The one thing the model does say about itself is its
ISA string, which is why `rv64i_zvl32b` is pinned and re-derived on demand. The smoke test may
not quietly upgrade our merge into the model's own word.

### Nothing here says a reference is usable

A reference becomes usable when a real matched-profile experiment has been run against it and
reproduced — not when its binary exists. What this work establishes is deliberately narrower:
*we have these binaries, this is exactly which ones they are, and each can be configured to
something close to this profile.* The experiment is the next leaf, and the difference between
those two sentences is most of what this milestone is about.

## The experiment, and the control that made it mean something

Having the models is not the milestone. `G0` asks for an evidence path that **works** — a real
matched-profile experiment, run and reproduced, covering a failure case and not only arithmetic.

Two guest programs were written, assembled by a 300-line assembler that reads its encodings from
a pinned table, and run on **both** Sail and Spike configured to the same profile:

| Experiment | What it exercises | Result |
| --- | --- | --- |
| `smoke-arith` | `LUI` sign-extension, the `*W` family, 6-bit *and* 5-bit shift amounts, 64-bit wrapping addition | both models agree over all 12 steps, and all 12 values match expectations derived from the specification |
| `smoke-trap` | a misaligned 4-byte load raising an address-misaligned exception | both models agree over all 3 steps, including the trap: cause `0x04`, `tval 0x80000401` |

Each reproduces byte for byte on a second run. One command re-runs all of it.

### Why the expected values were written before the program ran

An expected value copied out of a model's output tests that the model is self-consistent and
nothing else. So each of the twelve carries its derivation and its source locator — for example,
*"ADDIW ignores the upper 32 bits of rs1: it adds the sign-extended immediate to the low 32 bits
(0x80000000 + 1), discards overflow, and sign-extends the 32-bit result."* Falsifying a single
one of them fails the run, which is how we know the check is connected to anything.

### The control that matters most

Two models agreeing is a pleasant result and a weak one, until you can show the agreement is
*doing work*. So the Sail configuration was changed in exactly one respect — the misaligned-access
policy flipped back to "handled invisibly" — with the same binary and everything else untouched:

```
FIRST DIVERGENCE at aligned step 2
  sail-riscv   pc=0x0000000080000008 insn=0x40152083 writes=[('x1', 0)]
  spike        pc=0x0000000080000008 insn=0x40152083 writes=[]
```

One model loaded a value; the other trapped. **The models agree because the profile is matched**,
and that sentence is now a measurement rather than a hope. It also answers an open question the
profile had been carrying: the laboratory's contained-trap choice *is* expressible in the
reference's configuration, so no normalization at the comparator is required.

### What the specification could not supply

The pinned specification artifacts contain every semantic rule these programs rely on, in prose.
They do **not** contain the instruction encodings: the format diagrams are images, and a census
across all six pinned files finds zero seven-bit opcode patterns. The encodings therefore come
from a separately pinned machine-readable source, recorded as its own provenance — and that
source is upstream of both models, so "our bytes decode as expected" is *not* an independent
confirmation. It is independent for semantics, which is what the experiment is actually testing.

A coincidence worth reporting: that encoding source contains exactly **52** instructions for this
profile's extension set, and the profile — enumerated by hand from the prose, in an earlier leaf,
without reference to it — declares exactly 52. The symmetric difference is empty.

### Four differences, written down rather than smoothed over

Running two models surfaces disagreements that have nothing to do with semantics, and each was
recorded with its disposition: Spike refuses an ELF without a section header table while Sail
loads it; Spike runs a built-in reset vector before the entry point; Spike emits no commit record
for a trapping instruction; and Sail performs two 16-bit fetch reads per 32-bit instruction.

The third of those exposed a defect in the comparator itself. Before it was handled, comparing
only the overlapping prefix produced `AGREE over 2 aligned step(s)` for a run in which one model
trapped and the other stopped — a green verdict on a truncated trace. **A shorter trace is not
agreement**, and it is now a verdict that has to be explained before the run counts as evidence.

## Three models, and what their agreement is worth

The plan warned that two tools with different names are not two opinions. With two of them now
agreeing over fifteen steps, that warning became a question to answer rather than repeat, so the
ancestry was examined per subsystem and per pair — by reading both source trees, at the exact
commit the Sail binary reports for itself.

| Subsystem | Sail vs Spike | Evidence |
| --- | --- | --- |
| Instruction encoding | **not shared** | Spike generates `encoding.h` from `riscv-opcodes`; the Sail model hand-writes 59 files of `encdec` mappings and never mentions `riscv-opcodes` under `model/` |
| Floating point | **shared** | both vendor Berkeley SoftFloat; **184 of the 199 files present in both copies are byte-identical** |
| Integer semantics | no evidence of sharing | no textual reference in either direction |
| ACT vs Sail | **shared** | ACT computes its expected results with a configured Sail model |
| QEMU pairs | **not examined** | nobody has looked; recorded rather than omitted |

### The floating-point row

Both models vendor Berkeley SoftFloat — Sail Release 3e, Spike Release 3d — and `f64_add.c`
differs between the two copies by **one line**: the release number in a comment. For 184 of the
199 overlapping files, a differential floating-point test between these two models would execute
*one implementation twice* and report agreement. The agreement would be real, reproducible, and
worthless as independent evidence.

Nothing currently held is affected: this profile declares no floating point, and the experiment
compares integer semantics only. So the finding is routed forward to the milestone that
introduces floating point, with its measurement attached, rather than acted on here.

### The encoding row cuts the other way

This was not anticipated. The project's own assembler takes its encodings from `riscv-opcodes` —
the same source Spike generates from, and a source the Sail model does not use. So when Sail
decodes the emitted bytes as intended that is a genuinely independent confirmation of the
encoding, and when Spike does, it is not. **Independence is a property of a pair and a subsystem,
never of a tool.**

### "Not examined" is written down

Two pairs involving QEMU have no measurement at all, and they appear in the inventory saying so.
An omitted pair reads exactly like an independent one, and the distinction between *looked and
found nothing* and *never looked* is the whole value of the exercise. For the same reason, the
integer-semantics row says **no evidence of sharing** rather than *not shared*: no textual
reference in either direction rules out one model importing the other, and says nothing about
two authors having read the same third specification — which, for an ISA model, is the normal case.

The gate now enforces the discipline rather than trusting it: an experiment record that compares
two models is refused unless an independence record examines that pair. `not-examined` is a legal
verdict; silence is not.
