# P2 — the first validated profile

**Deliverable: a reusable CPU, not a boot test.**

Complete the declared scalar instruction scope and the laboratory environment scope. Cover
source requirements, boundary arithmetic, mode-independent state interactions, fetch and access
faults, suppressed effects, reserved cases, and controlled event boundaries where applicable.

## What "cover" means here

Four evidence routes, run against the same profile:

1. matched reference comparisons;
2. configured external test suites;
3. directed sequence tests aimed at interactions rather than single instructions;
4. compiled freestanding programs.

Report **coverage denominators**, not coverage percentages with an unstated base. Retain
minimised discrepancies — the reduced case is the artifact, and an unreduced failure is a story.

Demonstrate snapshot and replay only for the state boundaries actually implemented. A replay
facility that silently omits pending state is worse than none, because it produces confident
wrong answers.

## Gate CPU-LAB

The selected profile passes the full processor gate. That is a genuine, reusable deliverable.

Its machinery and its relevant scalar requirements transfer to P4 — but RV64 privilege,
address translation, atomics, and floating point are **new work with new evidence**. Nothing
about passing here shortens that.

## Done so far: P2-SCALAR.1 — the declared scope is fully exercised

The profile declares 52 RV64I forms; the four P1 smoke guests exercised 15 of them. Leaf
`.1` closed that gap with five scope-completion guests, every expectation value derived
from the pinned specification before any model ran (EVD-05):

- `scope-alu` — the 21 remaining logical, compare, shift and `*W` forms, plus `fence`
  (31 steps). The pairs are the point: `and`/`or`/`xor` on one operand pair, `slt`/`sltu`
  and `slti`/`sltiu` signed-against-unsigned on the same registers, `srl`/`sra` on one
  negative operand, `sllw` reading `rs2[4:0]` where a 6-bit read would differ, and the
  `sltiu` step whose immediate sign-extends *before* the unsigned compare. Two comparisons
  whose result is 0 are pre-written with 1 first, because the laboratory's observation
  vocabulary is the *visible* register change — a 0 into an already-zero register would
  leave no observation.
- `scope-mem` — the 8 remaining load/store forms (29 steps): sign- and zero-extending
  loads of the *same* bytes at the *same* addresses, a discarded `lw x0` (D-LOAD-X0 — the
  crossing happens, the value is dropped), and the three store widths with read-back.
- `scope-branch` — the 5 remaining branches, taken *and* not-taken each (19 steps from 24
  instructions), with five `never_written` registers as the negative observations.
- `scope-ecall`, `scope-ebreak` — the requested traps, one guest each, trap step last
  (cause 11 / cause 3, matching both references exactly).

Coverage is reported **with its denominator** and the report is a gate, not a narrative:
the 24th project doctrine `EXERCISE-COVERAGE`
(`scripts/check_exercise_coverage.sh`) re-derives the denominator from the dossier's scope
lists (a `count_total` that contradicts its own enumeration is refused), unions the
mnemonics the expectation documents declare executed, refuses any form no guest runs, and
resolves the `SCP-02` dependency closure through the one shared resolver. It fired RED
against the real corpus at 15/52 — all 37 missing forms named — before the guests landed,
and has read 52/52 since.

Three collateral findings, each owned: `fence` needed its `fm`/`pred`/`succ` operand
fields, which now come from the pinned `arg_lut.csv` like every other field — the fragment
and the assembler were extended, no opcode typed by hand. The trace adapter learned the
measured `ecall`/`ebreak` exception spellings of sail-riscv 0.14 and spike 1.1.1-dev. And
a suspected defect was logged against `.3`: a FENCE with a *reserved* `fm` value executes
as a nop where `D-FENCE` then said it must raise illegal-instruction — which `.3` measured
and **inverted**: the specification mandates the nop, the dossier was wrong and the model
right (see the `.3` section below).

## Done so far: P2-SCALAR.2 — the boundary domains are pinned

Form coverage asks "does every declared instruction execute"; boundary coverage asks the
harder question — does each operator behave at the *edges* of its domains. Five guests,
every expectation value derived from the pinned specification before any model ran
(EVD-05):

- `bound-shift` (89 steps) — the **6-bit shift-amount domain exhausted**: one `srli`
  sweep over all 64 amounts of `0x8000000000000001`, whose results are pairwise distinct
  so every step is a *visible* register change. `slli`/`srai` are pinned at
  {0,1,2,4,8,16,32,63} — every shamt bit on every form — and the register-amount corners
  `rs2 = 64` (a 6-bit read sees 0; the identity is pre-written with -1 so it stays
  visible) and `rs2 = -1` (reads as 63).
- `bound-shiftw` (55 steps) — the **5-bit domain exhausted** by one `sraiw` sweep, and the
  discriminator that makes the `*W` rule observable: `srl`/`srlw` on `rs2 = 96`, whose
  low-6 read is 32 and whose low-5 read is 0 — the same register pair shifts by 32 under
  `srl` and is the identity under `srlw`.
- `bound-arith` (31 steps) — `INT64_MAX + 1` and `INT64_MIN - 1` wrap, on the register
  *and* the immediate path; the `*W` wraps sign-extend from bit 31 while the operand's
  garbage upper half contributes nothing; `slt`/`sltu` at the signed extremes; and
  `auipc 0x80000`, whose sign-extended offset wraps the address sum modulo 2^64 to exactly
  4·n (D-ADDR-WRAP inside D-LUI-AUIPC).
- `bound-ext` (47 steps) — the sign edges 0x7F/0x80, 0x7FFF/0x8000 and
  0x7FFFFFFF/0x80000000, each read through the sign/zero **pair at one address** (the pair
  is the observation), plus store truncation at values that differ from both clamping
  outcomes.
- `bound-alias` (37 steps) — the little-endian lane proof (one `sd` of
  `0x0807060504030201`, then `lbu` at each of the 8 lanes), overlapping stores composed
  and read back (`sd` + `sb` over byte 3 + `sh` over bytes 6–7 + one `ld`), register
  aliasing (`rd = rs1 = rs2`, a self-referential shift, a load that overwrites its own
  base register — the address is sampled before the write commits), and x0 hardwired in
  both directions.

The corpus is now 14 guests agreeing with sail-riscv AND spike on **376/376 aligned
steps**, byte-identically reproducible. Notably, the gate's two RED moments this leaf were
the *author's* — a hand-assembled overlap-composition constant wrong twice, corrected both
times by re-deriving from the spec rule; the model was right throughout. An expectation
the spec rule does not compute fails the offline differential, so the correction
direction is forced the right way.

## Done so far: P2-SCALAR.3 — faults, suppressed effects and reserved cases

Scope coverage asks "does every declared form execute"; boundary coverage asks "does it
behave at the edges"; this layer asks the uncomfortable one — **does the model fail the
way the source says it fails**. Every reference behaviour below was *measured* against
sail-riscv 0.14 AND spike 1.1.1-dev by a probe suite before any guest was authored, and
eighteen guests then pinned the measurements as specification-derived expectations
(EVD-05), all agreeing three-way:

- **The defect that wasn't.** The `.1` scoping had logged: a FENCE with a reserved `fm`
  value nops where `D-FENCE` said illegal-instruction. The probes inverted it — the
  pinned specification *mandates* the nop, verbatim: "Base implementations shall treat
  all such reserved configurations as FENCE instructions (with fm = 0000)" (RVI-RV32I
  §1.1.7), and both references execute exactly as the model does. A reserved FENCE
  *configuration* is architecture-specified behaviour, not the UNSPECIFIED
  reserved-decode case. The dossier was wrong, the model was right: `D-FENCE` is
  corrected, and `fault-fence` pins the reserved-fm, FENCE.TSO, ignored-rs1/rd and
  pred/succ-zero configurations as nops on all three models.
- **The defect that was.** A misaligned `jal`/`jalr` wrote its link register *before*
  trapping; both references suppress the write — an instruction that raises a
  synchronous exception retires nothing. The fix was semantics *data*, not evaluator:
  the `jal`/`jalr` effect trees now check the target (`set-pc`) before the link write.
  `fault-jal-mis` / `fault-jalr-mis` pin it with `never_written x5`.
- **The word-less step.** A fetch access fault on a jump *target* is reported on the
  target (D-FETCH-FAULT-REPORT — the opposite reporting point from misalignment), and
  no instruction word exists there. The observation vocabulary learned the honest form:
  `run::Step.word` is `Option<u32>`, the runner emits the trap step with *no* word,
  and both trace adapters synthesize the same shape (spike reports epc = the target
  with no commit record; sail reports the trap with tval = the target). `fault-fetch`
  pins it three-way.
- **Reserved cases keep their source meaning** (SEM-07). The interpreter reports a
  reserved encoding as the UNSPECIFIED case it is (`Stop::Undefined`); the laboratory's
  declared `D-RESERVED-DECODE` policy — an act of the *harness*, never the
  interpreter — converts it to the illegal-instruction observation with tval = the
  offending word. Measured: both references report exactly that, so the converted
  observation compares three-way while the stop reason preserves the classification.
  `fault-reserved` (0xFFFFFFFF) and `fault-shiftw-res` (`slliw` with imm[5] = 1) pin
  it — and the second **closes dossier question OQ-2**: both current references treat
  the reserved `*IW` shift as illegal, the previous spec text's behaviour.
- **Suppressed effects** (SEM-06): a not-taken branch to a misaligned target raises
  nothing (`fault-branch-nt`, all six branch forms); a misaligned store is judged
  *before* the boundary — no store crossing exists, which the offline crossing log
  proves (`fault-st-mis-h/w/d`); a failing access modifies nothing
  (`fault-access-ld`/`fault-access-sd` at 0x40000000 — outside *both* reference
  platforms' maps, so the access-fault rule finally runs cross-model where
  `guest-no-device` could not).
- **D-LOAD-X0**: a load into `x0` still faults — pinned on the misaligned path
  (`fault-ld-x0-mis`) and the access-fault path (`fault-ld-x0-fault`).
- **D-HINTS**: the RV64I HINT table's ALU forms with `rd = x0` execute as nops that
  must not trap (`fault-hints`, including the NTL.P1 code point).
- **D-CODE-VISIBILITY**: a store over a later-fetched word is visible immediately —
  measured on *both* references first (spike's commit log even shows the store land),
  so the laboratory's choice is pinned three-way, not asserted (`fault-selfmod`).

One measured fact was **recorded, not exercised**: both references execute `fence.i`
although their matched ISA strings exclude Zifencei — a legitimate UNSPECIFIED
divergence the comparator cannot yet express. It lives in `references.sexp` as
`DIFF-FENCEI-EXECUTED`, and the guest that pins it is routed to `.4`.

The corpus is now **32 guests agreeing with sail-riscv AND spike on 454/454 aligned
steps**, byte-identically reproducible. The assembler learned a `.word` directive for
the raw reserved encodings its mnemonic path's range checks exist to refuse. The trace
adapter learned four measured spellings (`misaligned-fetch`, `store/amo-access-fault`,
`misaligned-store/amo`, and spike's `trap_instruction_address_misaligned`) — its
refusal on the third one fired mid-run, exactly as designed, and the guest corpus then
pinned it.
