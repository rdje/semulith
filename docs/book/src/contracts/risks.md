# Risks and decisions due

> **Orientation.** Fourteen ranked failure modes, each with an *observable* detection signal
> and a required response, plus the decisions that must be made before work depends on them.
>
> These are engineering risks, not a claim that any has occurred. What makes the register
> useful is the middle column: a risk whose trigger is "someone notices" is not managed. `RK01`
> fires when P0 cannot reproduce a matched arithmetic *plus* event/fault experiment; `RK06`
> fires when a known mutation passes or an expected value changes without a source reason.
>
> §2's table is the one to check before starting any milestone — it names what must be decided
> *before* that milestone's work depends on it, and what the current state of each decision is.
> Several read "candidates identified; not yet acquired", and keeping them reading that way
> until they change is the point.
