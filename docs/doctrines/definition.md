# Project doctrines — definition

The canonical definition — sources of truth, schemas, semantics, generation, citations. Part of
the partitioned project-doctrine registry: the bounded index is `DOCTRINE_ENFORCEMENT.md`
("This project's own doctrines"), the registry of record is
`scripts/check_doctrines.project.sh`, and REGISTRY-MIRROR judges this family's union with its
siblings as a mirror (`LIVE-CONTAINMENT.3`).

## This project's own doctrines — definition

| ID | Proves | Check |
| --- | --- | --- |
| `PROFILE-CONSISTENCY` | a profile dossier's declared counts equal the enumeration they summarise, and every decision carries an `authority` (`architecture` / `execution-environment` / `laboratory`) and a `source`. ⭐ The authority field is the load-bearing one: a **laboratory** policy over an `UNSPECIFIED` case must never read as an **architectural** rule, because a reference model that chose differently is then recorded as a defect instead of a profile difference. ⚠️ Honest limit: it proves the file is internally consistent and cites something — checking a citation against the specification is a human reading, which is why `scripts/fetch_sources.sh` exists to make the artifact being read identifiable | `scripts/check_profile_consistency.sh` |
| `RECORD-SCHEMA` | every tracked record file validates on its track: `.jsonl` files against their declared JSON schemas (the frozen `examples/`), converted `.sexp` catalogues against the schema layer (`schema/requirements.sexp`, `schema/contract-obligations.sexp`), read through the single mapping owner `scripts/records_sexp.py`. And the cross-checks: every `source_refs.source_id` names a source the profile's `sources.sexp` actually pins; a record may not be `research_status: resolved` while carrying an `OPEN:` note; every `(decision …)` in `profile.sexp` has a requirement whose statement is **identical**; every `dependencies` id resolves. ⭐ The resolved-with-an-open-question rule is the sharpest: both halves are individually true, which is what makes the pair the most convenient lie a requirements catalogue can tell. The JSON track runs on a tracked 180-line JSON Schema validator rather than a dependency — it **refuses** any keyword it does not implement — and, since `P1-LAB.7`, on the workspace's own Rust checker (`semulith check-examples`): the same JSONL records re-derived through a dependency-free Rust engine (the PACKAGE_CHECKS schema rows re-derived, not cited — RUST-01) plus the `docs/EVIDENCE_AND_GATES.md` §3 graph invariants (identifier references, profile scope, graph integrity, artifact hashes, evidence freshness, gate policy) over the frozen `examples/` bundle. ⭐ The Rust engine is the only half that can say `gate: passed`, and it cannot: the fixture evidence is deliberately `planned`, so the honest verdict stays `incomplete` — and the SEXP track refuses by name on an undeclared construct, field, arity, value type or field facet (`pattern`/`min-length`/`min`/`unique`). ⚠️ Named gap: closed by rules 6+7 (`P0-PROFILE.4`); the schemas' own `additionalProperties` lie (array values under a scalar-only declaration, never descended into) was measured and fixed by the move itself (`SOT-FORMAT.3`) | `scripts/check_requirements.sh` |
| `DOSSIER-SCHEMA` | every tracked dossier document (`profiles/*/*.sexp`) whose basename — or document family (`.expected.sexp` → `expectations.sexp`, `.override.sexp` → `override.sexp`) — has a schema validates against it through the one checker (`scripts/check_sexp_schema.py`), so a schema is a contract, not documentation: the mapping owner refuses undeclared fields but not facet violations, and this gate is what makes facet drift impossible to carry silently (the D-FENCE double-note lived unseen without it). Documents with no same-named schema are skipped and counted BY NAME in the verdict (`P3-BREADTH.7`; fired RED before registration against the pre-fix D-FENCE document recovered from git history) | `scripts/check_dossier_schema.sh` |
| `SOURCE-FORMAT` | every source of truth the engine extracts from is in the one format: no retired-format file (`.toml`/`.json`/`.jsonl`/`.yaml`) under `definitions/`, `schema/`, `profiles/`, `materials/`, and every `.sexp` there parses with `scripts/sexp.py` — the format split cannot return by accident, and "in the format" means the one reader reads it | `scripts/check_source_format.sh` |
| `UNIT-COMPOSITION` | a unit's composed encoding space is decided: the composition document validates against `schema/encoding.sexp` (undeclared constructs refused by name), its fragments resolve with dependencies met through the one shared resolver (`riscv_asm.resolve_composition` — a second resolver is how the `.2` regression happened), the union is collision-free, and a partial composition is declared — slots without `(status partial)` claim completeness while a hole is open, which is refused (`MODEL-COMPOSE.4`) | `scripts/check_unit_composition.sh` |
| `SEMANTICS` | the execution authority's corpus holds: every `definitions/**/*.sem.sexp` checks against its fragment — well-formed, complete, cited; a silent semantic override across fragments is refused (a declared `(refines (insn …))` is the only legal one, `MODEL-COMPOSE.6`); expansions bind exactly their base rule’s operands and quote its expansion sentence; raw-field mappings and own-rule alternatives are checked (P4-SYSTEM.12 slice b); locators from rules AND expansions resolve offline, with a named skip — never a green lie — when the cache cannot judge | `scripts/check_semantics_corpus.sh` |
| `EXTRACTION` | the definition is sufficient for an engine: every declared instruction has an encoding AND semantics AND a requirement (one set, four ways), every state element a reset, every obligation both checks; the verdict `P1-LAB` cites (`MODEL-METHOD.10`) | `scripts/check_extraction.sh` |
| `SCOPE-COVERAGE` | no model code against an uncovered scope: the registry declares each scope's required categories; a required one `missing` or absent refuses — `P1-LAB`'s precondition, composed with EXTRACTION (`MODEL-METHOD.6`) | `scripts/check_scope_coverage.sh` |
| `STATE-GEN` | the generated state module is still the byte-exact function of its descriptor: `crates/semulith-core/src/state.rs` regenerates from `profiles/rv64i-lab-v0/state.sexp` by `scripts/gen_state.py`, drift is refused with the regeneration command, and the generator itself refuses — naming the construct — any descriptor shape it cannot emit (another profile, a declared register family / memory space / hardware stack, a missing xlen, a non-64 width, an unmapped special register, a missing SEM-08 census), so "generated" stays a governed claim rather than a hope. The owner→mirror pair is registered in `doctrine/fact_ownership.tsv`; fired RED against a hand-edited module before registration | `scripts/check_state_gen.sh` |
| `DEF-GEN` | the generated definition module is still the byte-exact function of the canonical definition: `crates/semulith-core/src/definition.rs` regenerates from the unit's encoding composition and the semantics data by `scripts/gen_definition.py`, carrying OWN-03's manifest (definition, generator, configuration and source fingerprints) as data. Drift is refused with the regeneration command; the generator itself refuses — naming the construct — a shape it cannot emit (another unit, an unsupported ilen, an instruction without semantics, an operand reference the encoding does not provide, a missing semantics document), and a check that cannot judge refuses (exit 2) rather than reporting a verdict. The owner→mirror pairs are registered in `doctrine/fact_ownership.tsv`; fired RED against a hand-edited module before registration. C’s conditional lowering is checked on a temporary composition: spec-side register/immediate limits, emitted mappings/effects, rustfmt stability and a compiled specificity decoder; wrong mapping and reversed ordering controls are RED (P4-SYSTEM.12 slice b). The tracked C evaluator is compiled on a temporary full composition; eighteen extent/width/exception cases must pass and erased-width/word-fetch/short-ILEN mutations must fail behaviorally (slices c2/d3d0) | `scripts/check_definition_gen.sh` |
| `GUEST-GEN` | the generated guest fixture is still the byte-exact function of the tracked guests and their specification-derived expectations: `crates/semulith-verify/src/guests.rs` regenerates from `profiles/rv64i-lab-v0/guests/` (the independently encoded programs and the EVD-05 expectations derived from the pinned specification) by `scripts/gen_guests.py`, carrying OWN-03's input and generator fingerprints. Drift is refused with the regeneration command; the generator refuses — naming the guest and step — a source that does not assemble, an expectations document with a missing/duplicate/out-of-range step, or a register outside x0..x31, and a check that cannot judge refuses (exit 2). The owner→mirror pairs are registered in `doctrine/fact_ownership.tsv`; fired RED against a hand-edited fixture before registration. A temporary C composition checks 37 hand-encoded words, operand refusals and exact byte labels/images; compact-register, word-stride and padding mutations must fail (P4-SYSTEM.12 d1). A generated mixed-length byte fixture executes through the tracked runner on a temporary C composition; padding/loader mutations must fail (d2). The tracked spec-side author re-derives its explicit historical corpus; reserved upper bits and SUM/MXR/U permissions are checked, and six author mutations must fail (d3a). The tracked Sail adapter requires ordinary rows and witnessed delivery gaps; failed processes, unwitnessed gaps, missing rows and stale-output reuse are behavioral RED controls (d3b). Independent spec-side C decoding/execution checks all 37 forms, scattered one-bit fields and original traps; six C author mutations must fail (d3c). Independent parcel fetch fixtures check Sv39 canonical/reserved/non-leaf rules, MPRV, exact attempts and original EPC/fault VA; nine walk/fetch mutations must fail (d3d1). Selected counter/timer enables and literal-string/schema round-trips have eight mutations and three formerly refused guests matching 117 steps (e1b2) | `scripts/check_guest_gen.sh` |
| `CITATION-QUOTES` | a quoted phrase a tracked `.sexp` attributes to a pinned section occurs IN that section (four decidable attribution rules; ellipsis pieces in order; a miss names where the phrase is). `check_citations.py` proves a locator exists; this proves its quote is there — RED on the real `RVI-F §20.1.1` corpus before registration. ⚠️ Quotes only; unattributed quotes counted; PDF pins UNCHECKABLE; no pinned pages → NAMED SKIP | `scripts/check_citation_quotes.sh` |
| `FP-VECTORS` | `crates/semulith-core/src/fp/tests/vectors.rs` (the floating-point model layer's directed unit vectors — the rules) and `fixtures.txt` beside it (seeded fixtures at scale over every operation × format × mode — the breadth, `P4-SYSTEM.7` slice e2) are the byte-exact output of `scripts/gen_fp_vectors.py` over the spec-side exact-rational IEEE reference `scripts/specfp.py` (fractions/decimal: neither SoftFloat, the backend, nor MPFR); a hand-edited expected value in either is DRIFT. ⭐ It also judges the REFERENCE: every run re-checks specfp's round-to-nearest-even add/mul/div/sqrt and its double→single narrowing (and exact widening, slice d3) against the host's hardware IEEE on directed exact ties and seeded cases — a reference whose tie rule drifted is refused (fired RED: a half-up mutation, which 1,313 random cases alone had missed). Founding failure (`P4-SYSTEM.7` slice c4): the slice-(a) MPFR oracle judged OF on the exact magnitude and UF on the delivered result — against IEEE §7.4/§7.5 — and agreed with the backend because it shared the backend's convention. ⚠️ The hardware leg is RNE only; directed modes rest on the reference's quoted rules and the recorded 63,480-case agreement | `scripts/check_fp_vectors.sh` |
| `CONTRACT-FREEZE` | a unit's environment contract is VERSIONED, not edited in place: `profiles/<unit>/contract.sexp` holds one `(contract …)` per version (schema/contract.sexp) listing the obligation records it adds; every record in `contract-obligations.sexp` belongs to exactly one version and carries that version's contract_id/contract_version; a FROZEN version pins each member's record line by sha256, so an edited record is refused; `extends` names the version one lower; a `supersede` replaces an inherited record by one of the version's own. Founding gap (`P4-SYSTEM.9`'s brief): the version was a string repeated on every record that nothing checked, and seven leaves added records under v0 | `scripts/check_contract_freeze.sh` |
